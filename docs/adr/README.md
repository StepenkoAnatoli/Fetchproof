# Architecture decision records

Decisions this project has already made about its own shape. An architecture review should
not re-suggest what is recorded here; if a decision is wrong, write a new ADR that supersedes
it rather than quietly undoing it.

The protocol-level decisions — evidence must be fetched not typed, the gate fails open and
loud, the two overrides, the machine-wide `core.hooksPath` — are recorded in
`research/DISCOVERY.md` under **Already decided**, and in
`docs/superpowers/specs/2026-09-13-research-gate-hardening-design.md`. Those predate this
directory and are treated as ADR-equivalent.

| [0020](0020-five-trusted-boundaries-that-did-not-hold.md) | Five trusted boundaries that did not hold, fixed as one class: no data reaches a **shell** (argv + `shell: false`, the Windows `.cmd` route validated and refusing rather than re-quoted); the collector's **lock** is `O_EXCL`, so exclusivity is the kernel's decision, with an unidentifiable fresh holder waited for rather than broken; a **path list** is data on a pipe, never a growing argv, and a watchdog kill is a named internal error; platform **text handling** is pinned (`.gitattributes` in the repo *and* the template) and a body-hash mismatch is *classified* — line-ending rewrite vs. tampering — so the remedy names the right machine; and the machine **config default** is read in three states, where an unreadable config holds the last one that parsed and otherwise fails closed. Four shared rules: the guarantee belongs to the platform; a data channel is not an argument channel; classify rather than guess; a hardening never moves towards allowing on its own. Refines 0002 and 0011, both left unedited |

One test at a time in registration order (concurrency rejected: shared temp state); a per-test watchdog (`RESEARCH_KIT_TEST_TIMEOUT`, 60s, chosen by measurement — the suite runs in 9s); a timed-out test's promise swallowed so its late rejection cannot crash the runner. | [0027](0027-search-and-fetch-are-two-seams.md) | **Search and fetch are two seams**, not one adapter: `selectTransport` resolves a fetch provider and a search provider independently, `FETCH_SHAPE`/`SEARCH_SHAPE` are declared, and the return value is *extended* (`{ name, adapter, why }` still means the fetch side) so no existing caller changes. | [0028](0028-the-bundle-is-a-received-state-not-a-live-constraint.md) | The bundle is a **received state, not a live constraint**: `BUNDLE_INDEX.md`'s digests are frozen at the 2026-09-17 handover and never regenerated, because a hash file rewritten whenever it disagrees with reality records nothing. The trade ADR-0022 described was inverted: nothing had ever read those digests, while the map rule is checked mechanically on every commit and caught four real documentation errors in three days. `lib/bundle.mjs` makes the record checkable instead of decorative — unchanged / changed-and-expected / changed-and-**not**-expected, with `EXPECTED_TO_DRIFT` naming only the files the project's own rules require to move |

| [0029](0029-the-validator-layer-arrives-as-a-source-not-a-donor.md) | The validator layer arrives as a **source, not a donor**: the release-evidence modules ADR-0022 deferred turn out to exist on this machine - 1,700 lines, 12 schemas, 61 passing tests - in a tree that is **not a git repository** and has diverged from this one. Absorbing them in one commit would be the project failing its own premise, since it refuses an unaccounted *capture* and could not coherently exempt code. | [0032](0032-one-artifact-contract-for-every-consumer.md) | **One artifact contract for every consumer, and authorization is DERIVED rather than asserted.** One versioned ZIP serves the AI agent, the Actions workflow, the future Windows app and a person with unzip: `manifest.json` is the machine entry point, `README-FIRST.md` the human one, and the producer renders the second from the first so they cannot disagree. `createArtifact` takes no authorization argument and the CLI has no `--build-authorized` — `state`, `kind`, `buildAuthorized`, `review.*` and `gate.*` all come from running the real gate, with `env` defaulting to `{}` so a packaging shell's `GATE_OFF` cannot leak into a package that outlives it. `findingsReviewed` is answered negatively rather than graded: a Finding still byte-identical to the extractor's output was demonstrably never rewritten (the line ADR-0013 drew, uncrossed). | [0033](0033-the-collector-refuses-rather-than-degrades.md) | **The collector refuses rather than degrades, and no dispatch input reaches a shell.** `collect.yml` implements ADR-0031 against ADR-0032's contract, separate from `live-collection.yml` because "does the adapter work" and "collect this, for a person, now" deserve different approvers. The honest limit is written in the file: GitHub exposes no scope information, so the marker proves the environment was configured and **cannot** prove a repository-level value did not serve the secret. No `http-keyless` fallback: a missing credential refuses rather than shipping a quietly worse corpus under the same artifact name. The test enforcing that scans every workflow and found `live-collection.yml` had been doing it since it was written; fixed here **Amended the same day**: the required reviewer is dropped and the environment kept. A reviewer approving a *dispatch* is a spend gate, not a review — nothing is collected yet to judge — and it makes autonomous dispatch impossible. The environment stays because it was never about approval: it is the only place the credential is unreadable by every other workflow. Spend is bounded by `max_pages`, the depth tier and the vendor's 402-at-zero cap. The control that replaces the reviewer is **token scope**: a fine-grained PAT with `Actions: read and write` on one repository, driven by `bin/collect-remote.mjs`, which takes **no `--token` flag** and redacts by pattern rather than by remembering its own value |
