# Discovery Contract - has Tavily's exclusion expired?

Started 2026-09-22. This file is the definition of "enough information to build".
`node fetchproof/bin/preflight.mjs` reads it and blocks the build until every unknown
below is either `CLOSED` with evidence or `KNOWN-UNKNOWN` with a verification step.

## Build intent

Constraint **C-6** excluded Tavily from the search seam on 2026-09-19
(`docs/requirements-2026-09-19-search-fetch-seam.md:55`, citing §6.5 and §6.7 of the terms),
and line 136 of the same document recorded the trigger: **"Revisit if a no-training tier
ships."** ADR-0027 then leaned on that disqualification to argue the same disclosure test
against SerpAPI, which is why the exclusion is load-bearing and not a preference. The operator asked whether Tavily should
replace SerpAPI. This checks the trigger before any key is wired, which is the order
C-6 requires - the exclusion was about terms, so the terms decide.

"Done" is a yes or no on that trigger, read from the terms as they stand today. Nothing is
built either way: the output is a decision to leave C-6 alone or to reopen it.

**A prior was registered before collecting.** It expected the exclusion to stand, since the
original reading was only three days old, and admitted not knowing whether a no-training
tier or a data opt-out existed. Both parts held.
